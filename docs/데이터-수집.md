# 보정용 측정값 수집 (Supabase)

판정 기준(길·평·흉 경계와 형 판정 기준값)을 실제 사용자 분포로 다시 계산하기 위해, 사용자가 동의하면 **얼굴 비율값만** Supabase에 모은다. 사진·얼굴 좌표·이름·생년월일·위치는 보내지 않는다. 유료 주문·결과와 같은 Supabase 프로젝트를 쓰되, 표는 따로 둔다.

```
앱(브라우저) ──anon 키──▶ RPC submit_calibration (검사·횟수 제한) ──▶ 표 calibration_samples
                                                                         │
                    scripts/calibrate.mjs ◀── 서비스 키로 읽기 ─────────┘
                              │
                    src/lib/physiognomy.js 의 BASE 갱신
```

## 1. Supabase 준비 (한 번만)

1. supabase.com에서 프로젝트를 만든다. 지역은 **Northeast Asia (Seoul)**.
2. 표와 함수 만들기 — 둘 중 하나:
   - 대시보드 **SQL Editor**에 [`supabase/migrations/20261007000000_calibration.sql`](../supabase/migrations/20261007000000_calibration.sql)을 붙여 넣고 실행.
   - 또는 Supabase CLI: `supabase link --project-ref <ref>` 후 `supabase db push`.
3. **Project Settings → API**에서 두 값을 복사한다.
   - Project URL (`https://<ref>.supabase.co`)
   - `anon` public 키

## 2. 앱에 연결

GitHub 저장소 Settings → Secrets and variables → Actions → **Variables**에 추가:

| 이름 | 값 |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon 키 |

다음 배포부터 결과 화면 아래에 '측정값 기여하기' 카드가 나타난다. 로컬에서는 `.env.local`에 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`를 넣는다.

anon 키는 공개돼도 되는 키다. 표에 행 수준 보안(RLS)을 켜고 정책을 두지 않았기 때문에 anon 키로는 표를 읽거나 직접 쓸 수 없고, `submit_calibration` 함수만 부를 수 있다. 함수가 막는 것:

- 형식 검사: 버전, 기기 ID(UUID), 성별·연령대·이마 상태 목록, 지표 이름 규칙, 값 범위(−20~20), 삼정 비율(0.05~0.9)
- 같은 기기에서 6시간에 10번까지 (반복성 확인용으로 여러 번은 허용)

**서비스 키(service_role)는 브라우저·저장소에 절대 넣지 않는다.** 보정 계산을 돌릴 때만 환경 변수로 쓴다.

## 3. 표에 쌓이는 것

`calibration_samples`, 한 행 = 한 번의 측정.

| 열 | 내용 |
|---|---|
| created_at | 받은 시각 |
| v | 형식 버전(2) |
| device | 기기마다 임의로 만든 UUID. 사람을 알아볼 수 없고, 같은 사람의 반복 측정을 묶는 데만 쓴다 |
| gender, age_band | 사용자가 입력한 경우만 |
| forehead | visible / covered / unclear |
| thirds | 이마가 드러난 경우 삼정 비율 [상, 중, 하] |
| metrics | 얼굴 비율값 `{이름: 값}` (`src/lib/contribute.js`의 METRIC_KEYS). 이름:값이라 지표가 늘어도 표를 바꿀 필요가 없다 |

## 4. 기준 다시 계산하기

```bash
SUPABASE_URL=https://<ref>.supabase.co SUPABASE_SERVICE_ROLE_KEY=<서비스 키> node scripts/calibrate.mjs
```

(대시보드 Table Editor → Export → CSV로 받은 파일을 `node scripts/calibrate.mjs <파일>`로 줘도 된다.)

출력:
- 지표별 인원·평균·표준편차·사분위, 남녀 평균
- **반복성(ICC)**: 같은 사람을 여러 번 찍었을 때의 흔들림 대비 사람 간 차이. 0.5 미만이면 "사람 구별 못 함" 표시 → 그 지표는 판정에서 빼거나 '참고'로 둔다.
- `BASE`에 붙일 값(30명 이상 모인 지표만 바꾸고 나머지는 기존 값 유지)

출력된 `BASE`를 `src/lib/physiognomy.js`에 반영하고 `npm test`.

### 목표 표본

| 단계 | 필요한 것 |
|---|---|
| 반복성 확인 | 20명 × 각 5번 (같은 기기에서 다시 찍어 보내기) |
| 베타 기준 | 남녀 각 50명 이상 |
| 정식 기준 | 남녀 각 150명 |
| 형 분포 확인 | 30명 이상 — 오관 형이 한두 개로 몰리지 않는지 |

같은 사람이 여러 번 보내도 분포 계산에는 기기별 평균 한 번만 들어간다.

## 5. 한계

- 기기 ID는 브라우저 저장소에 있어서, 저장소를 지우거나 다른 브라우저를 쓰면 다른 사람으로 잡힌다. 횟수 제한은 스팸을 완전히 막지 못한다. 계산 전에 같은 시각 대량 제출, 같은 값 반복 같은 묶음을 한 번 확인한다.
- 서울 리전에 저장한다. 동의 문구의 저장 위치를 이에 맞춘다.
